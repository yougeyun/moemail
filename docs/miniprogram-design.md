# 临时邮箱系统：小程序与账号体系设计方案

## 一、总体目标

- 微信小程序与网页端共用同一套账号、邮箱、邮件和会员数据。
- 邮箱成为账号主身份，微信 openid 作为绑定身份，两端最终收敛到同一个账号。
- 小程序接入微信流量主广告，并通过激励视频提供“看视频增加邮箱额度”的补充方式。
- PC 端去除 GitHub/Google 登录，改为邮箱密码登录 + 微信小程序扫码登录。
- 全站用户可见内容不再出现 moemail 字样，统一使用网站名称或域名。

## 二、账号模型

### 2.1 基本原则

- 一个邮箱只属于一个账号，邮箱是唯一登录身份。
- 一个微信 openid 只绑定一个账号。
- 邮箱可先注册后绑微信；微信可先登录后绑邮箱。
- 禁止通过“同一邮箱重复注册”或“同一微信重复建号”产生账号分裂。

### 2.2 账号状态

1. 邮箱账号，未绑定微信：可以正常登录，个人中心提示绑定微信。
2. 微信账号，未绑定邮箱：可以进入小程序，但创建邮箱、发信等核心能力应在绑定邮箱后开放。
3. 邮箱 + 微信已绑定：完整账号，两端通用。

### 2.3 防重复与防冒用

- 绑定已有账号时，必须同时校验“邮箱验证码”和“原账号密码”，防止他人通过邮箱验证码冒绑账号。
- 绑定邮箱时若邮箱已属于其他账号，直接拒绝并引导登录原账号。
- 微信 openid 已绑定时，再次登录直接进入原账号，不创建新账号。
- 注册新账号时邮箱必须未注册，且通过验证码或激活邮件确认邮箱归属。

## 三、邮箱验证与激活邮件

### 3.1 系统发件通道

内置 Resend 发件功能不再作为依赖，新增独立的系统发件通道，用于发送注册验证码、激活邮件、绑定验证码。

- 初始方案：使用 QQ 邮箱或网易邮箱的 SMTP 服务，适合小规模验证邮件。
- QQ 邮箱 SMTP：`smtp.qq.com`，SSL 465 / STARTTLS 587，需开启 SMTP 服务并使用客户端授权码。
- 网易邮箱 SMTP：`smtp.163.com`，SSL 465 / 994，同样需要客户端授权码。
- 免费个人邮箱 SMTP 有较严格的日发送量、发送频率和 IP 限制，只适合起步阶段；用户量上升后建议切换为企业邮箱或专业邮件服务。
- SMTP 发件地址必须是该邮箱本身；若希望使用自己的域名作为发件地址，建议后续使用腾讯企业邮、网易企业邮或阿里云邮件推送。
- 后台可配置 SMTP：host、port、username、password、from 名称、from 地址、TLS/SSL。
- 系统发件通道与用户正常发信通道分离，避免互相影响。
- 发件逻辑抽象为统一邮件接口，后续可以切换到阿里云 DirectMail、腾讯云 SES、自定义 HTTP 邮件接口等，不需要改业务代码。
- 实现方式：Cloudflare Pages Edge 运行时不能直接使用 Node 的 SMTP 库。优先在现有服务器上部署一个 HTTPS 邮件中转接口（PHP + PHPMailer），云端应用通过该接口发送 QQ/网易 SMTP 邮件；备选方案是基于 Worker sockets 实现 SMTP 客户端。
- 后台增加“测试发信”按钮，保存 SMTP 配置后可以先发送一封测试邮件验证。

### 3.2 验证模式

后台提供“账号验证模式”配置，适用于新用户注册和邮箱绑定：

- 验证码模式：发送 6 位数字验证码，5-10 分钟有效，用户输入后完成验证。
- 激活邮件模式：发送一次性激活链接，用户点击后完成验证。

相关配置：

- 验证码有效期
- 激活链接有效期
- 重发间隔，建议不低于 60 秒
- 单邮箱单日发送上限，建议 5-10 封
- 验证尝试次数上限，建议 5 次

### 3.3 验证码安全

- 验证码保存在 KV 或 D1，带过期时间和尝试次数。
- 校验失败超过次数后作废，必须重新发送。
- 注册接口继续保留 Turnstile 或同类防机器人校验。
- 验证码邮件只发送到用户填写的邮箱，响应中不返回验证码。

## 四、小程序端设计

### 4.1 视觉方向

- 主色：青瓷绿 `#0F9D7C`
- 强调色：暖橙 `#F97316`，用于广告、激励视频、奖励
- 微信绿：`#07C160`，仅用于微信登录/分享
- 页面底色：`#F3F6F7`
- 正文墨色：`#17202A`

采用微信原生控件习惯，底部 TabBar 三个入口：邮箱、收件箱、我的。

### 4.2 页面与功能

1. 开屏 / 插屏广告：启动后展示，可跳过，广告位由后台配置。
2. 登录与绑定：微信头像昵称填写、微信一键登录、绑定已有账号、注册新账号。
3. 邮箱首页：可用额度、邮箱列表、复制/分享/删除、创建入口、Banner 广告。
4. 创建邮箱：前缀、域名、批量数量、有效期，额度不足时引导激励视频。
5. 激励视频弹窗：看完整视频增加邮箱额度，默认每日 3 次。
6. 收件箱：当前邮箱切换、未读状态、下拉刷新、定时轮询、Banner 广告。
7. 邮件详情：邮件元信息、HTML 预览、回复/转发/复制/分享。
8. 写邮件：发件人选择、收件人、主题、正文、每日发信余量。
9. 我的：用户信息、会员等级、统计、激活码兑换、会员中心、激励视频入口。

### 4.3 微信登录与绑定流程

1. 用户点击登录，调用 `wx.login` 获取临时 code，后端换取 openid。
2. 用户主动选择头像、填写昵称（微信不允许静默获取真实头像昵称）。
3. 进入账号处理页：
   - 绑定已有账号：邮箱 + 原账号密码 + 邮箱验证码。
   - 注册新账号：邮箱 + 密码 + 邮箱验证码。
4. 绑定或注册成功后，微信 openid 与该邮箱账号完成绑定，后续自动登录。

## 五、PC 端改造

### 5.1 登录与注册

- 移除 GitHub/Google 登录入口和 NextAuth Provider 配置，不再保留隐藏入口。
- PC 新用户注册：邮箱 + 密码 + 验证码或激活邮件。
- PC 登录：邮箱 + 密码。
- 老用户迁移：原有 GitHub/Google 账号在两种登录被移除后无法再登录，需要在迁移期提供“补邮箱 + 设置密码”或“绑定微信”的流程，否则这些用户会永久无法登录。

### 5.2 PC 微信扫码登录

- PC 端生成带临时参数的微信小程序码。
- 用户使用微信扫码打开小程序，在小程序内确认登录。
- PC 端轮询确认结果后写入登录态。
- 该方案不依赖微信开放平台“网站应用”资质，和现有小程序强绑定。

### 5.3 绑定引导

- 邮箱账号未绑定微信：个人中心显示“绑定微信”，扫码确认后完成。
- 微信扫码新用户未绑定邮箱：登录后引导绑定邮箱，未绑定前限制创建邮箱、发信等核心能力。
- 建议采用“待办引导 + 个人中心提示”，不强制每次登录弹窗。

## 六、广告与激励视频

### 6.1 广告位

- 开屏/插屏广告：启动后展示，使用微信插屏或封面广告位。
- Banner 广告：邮箱首页、收件箱中间。
- 激励视频：创建邮箱弹窗和“我的”页面。

### 6.2 流量主

- 微信流量主有 UV 门槛，一般在累计独立访客达到 1000 左右后开放。
- 所有广告单元 ID 在后台配置，未填写时小程序不显示广告，不影响正常功能。

### 6.3 激励视频奖励

- 默认规则：看完一次完整视频 +1 个邮箱额度，每日最多 3 次。
- 奖励数量、每日上限、奖励有效期全部后台可配置。
- 后端必须限频并按用户记录发放记录，防止伪造客户端完成事件。
- 奖励额度作为独立来源记录，与激活码额度区分，方便对账和追溯。

## 七、品牌替换

- 全站用户可见文案不再出现 moemail、MoeMail、moemail.app。
- 所有品牌位置使用后台配置的网站名称、网站标题、网站描述、当前域名。
- 需要替换的范围包括：i18n 文案、页面标题、HTML meta、邮件模板、Logo、默认域名、错误提示、分享文案、小程序名称与页面文案。
- 代码目录、仓库名、数据库表名不受此限制。

## 八、后端与数据模型改动

### 8.1 新增数据

- 邮箱验证码记录：邮箱、验证码/激活 token、过期时间、尝试次数、用途。
- 微信账号绑定：openid、unionid、用户 ID，可复用现有 OAuth accounts 表。
- 激励视频奖励记录：用户、奖励数量、有效期、发放时间。
- 邮箱额度来源标记：区分激活码、激励视频、后台发放，便于对账。

### 8.2 新增接口

- 发送验证码 / 激活邮件
- 校验验证码
- 邮箱注册
- 微信登录（code 换 openid）
- 绑定已有账号（邮箱 + 密码 + 验证码）
- 微信绑定/解绑
- PC 扫码登录：创建二维码、小程序确认、PC 轮询
- 激励视频奖励发放
- SMTP 配置与测试发送
- 账号验证模式配置

### 8.3 现有系统可复用部分

- 用户表已有 `email`、`emailVerified` 字段。
- NextAuth accounts 表可存放微信 openid。
- 激活码额度体系可扩展为广告奖励额度。
- 现有邮箱、邮件、发信、会员接口直接供小程序复用。

## 九、分阶段计划

### 第一阶段：账号与后端

- 新增 SMTP 系统发件通道和邮件发送抽象层。
- 验证码/激活邮件注册与绑定。
- 微信登录与账号绑定接口。
- PC 端邮箱注册、移除 GitHub/Google。
- 老用户迁移与全站品牌替换。

### 第二阶段：小程序基础版

- 小程序骨架、登录绑定页、邮箱首页、收件箱、邮件详情、写邮件、我的。
- 与网页端共用同一套数据。

- [x] 激励视频额度发放与防刷。

### 第四阶段：PC 微信扫码登录与增值能力

## 十、风险与合规

- 小程序审核：临时邮箱和发信功能可能被审核重点关注，建议先准备用户协议、隐私政策、防滥用说明。
- 广告审核：流量主开通有门槛，广告内容需符合微信规范。
- 账号安全：绑定已有账号必须同时校验密码和验证码；验证码接口必须限频。
- 发件信誉：系统发件域名需要配置 SPF/DKIM，否则验证码邮件容易被判为垃圾邮件。
- 老用户迁移：GitHub/Google 登录移除前必须提供补邮箱/设密码或绑微信的通道。

## 十一、待确认事项

1. SMTP 最终实现方式：Worker 原生 SMTP 客户端，还是先接 HTTP 邮件 API 中转。
2. 账号验证模式默认值：验证码还是激活邮件。
3. 激励视频默认参数：每次 +1、每日 3 次是否需要调整。
4. PC 新邮箱用户是否必须绑定微信，还是仅提示引导。
5. 小程序底部 Tab 是否保持“邮箱 / 收件箱 / 我的”三个。
6. 全站品牌替换后的正式网站名称和显示域名。

## 十二、已确认决策

- 系统验证邮件使用 QQ 邮箱或网易邮箱 SMTP，起步阶段接受其发送量限制。
- 邮件发送抽象为统一接口，后续可无痛切换其他邮件服务。
- 绑定已有账号必须同时填写原账号密码和邮箱验证码。
- 后台可配置“验证码模式”或“激活邮件模式”。
- GitHub/Google 登录彻底移除，不保留隐藏入口。
- 全站用户可见内容不再出现 moemail 字样。
- 小程序 UI 以当前 HTML 原型为基础，采用青瓷绿 + 暖橙 + 微信绿的视觉方向。
